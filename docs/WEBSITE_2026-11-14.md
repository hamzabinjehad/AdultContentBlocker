# Hisn website: a calm product page for the Android app

Date: 14 November 2026. Status: the static site is built, tested in headless
Chrome and served locally. It is **not hosted** and has no domain yet. The
download is the last signed Android build, **1.5.3 direct**; the 1.6.0 candidate
is shown as in development. The Vault moved to `/vault.html`; `/` is now the
product page.

## Why the site changed

The repository already had the Vault, a privacy page and a lot of release
records, but no product page and no working download path. The task was to make
the website ready to publish the Android app and to show that the other
versions are coming. The page therefore needed:

- one obvious free Android download;
- a plain account of the layers, the phone-making checks and the limits;
- honest status labels for Android 1.6.0, Mac, iPhone/iPad, the extension and
  the Vault;
- no invented ratings, testimonials or user counts;
- English and Arabic, light and dark;
- a static, CSP-locked build with no analytics.

What we deliberately did **not** copy:

- ratings, “featured in” logos, download or user counts — Hisn has no published
  user numbers and inventing them would be a lie;
- testimonials or video quotes — no release evidence exists for public quotes;
- countdown discounts, paywalls, “you will quit by” projections and shame
  slides;
- an account before the first setting.

What we did take: the **structure** (centered hero promise, layered phone,
stat band, three benefits, step cards with real app screens, FAQ, final CTA),
the **atmosphere** from Unchaind (soft moving aura, calm space, layered
screens) and the **visual energy** (large bold headline, pill CTAs, platform
pills, rounded cards). The implementation, animation and all copy are Hisn’s
own.

The public page carries **no developer metadata**: no version code, APK/SHA-256,
certificate, checksum link, repository/source link, “no signed artifact” or
“no phone acceptance” language. The release identity still lives in
`website/release.json` and is checked by `stage-downloads.sh` before a build;
it is simply not part of the customer page.

## The download

The public page offers the Android app as **free** and links a stable
`downloads/hisn-android.apk`. Internally that file is the signed **1.5.3
direct** build, version code 41, from `dist/android-1.5.3-end/`:

- bytes: 31,290,641; SHA-256
  `e138f39d94965f9c116e1d2ed9cd893cb978a4a536ba604b242b6d28d00a7d14`;
- certificate SHA-256
  `2F:BE:D6:57:E6:AB:C7:1C:15:CA:D0:CD:99:1C:53:2F:59:77:2D:16:95:D7:C3:7E:65:A1:14:38:5E:94:70:C5`;
- `release.json` is the single source for the identity;
  `website/stage-downloads.sh` refuses to stage a file whose size or hash
  differs and copies it to the stable public name `hisn-android.apk`;
- the APK is not committed. `build-site.sh` stages it into
  `dist/hisn-website-<date>/downloads/` under the stable public name and writes
  a zip. `release.json`, the checksum file, the build log and the vendor notice
  are **not** copied to the public output; the vendored runtime keeps its
  license.

There is **no signed 1.6.0 artifact** in this tree, so the public page labels
the next Android update as **coming soon** rather than offering a second
download. It does not show the source version, the signing state or the Play
upload state; those stay in the release records.

## Motion and CI

- **The motion library is vendored, not loaded from a CDN.** anime.js 3.2.2
  (MIT) is in `website/lib/vendor/anime.min.js` with its license. The CSP can
  stay `script-src 'self'` and `connect-src 'none'`.
- **`lib/motion-flag.js`** adds the initial hidden state only when the reader
  has not asked for reduced motion, and removes it after 2.6 s if the animation
  script never starts. **`lib/animations.js`** runs the hero entrance, the
  layered-phone reveal and the section scroll reveals. Without JavaScript or
  with `prefers-reduced-motion: reduce`, the finished page is visible.
- **GitHub Actions** runs the site tests and a headless Chrome pass on
  `ubuntu-24.04`; the workflow is a check, not a deploy. The APK is still
  staged from the owner’s signed `dist/` at release time.

## Limits

- **No hosting or domain.** The built folder and zip are ready to upload; the
  owner still has to choose a host, a domain and HTTPS. The site has no server
  component.
- **The download is 1.5.3, not the 1.6.0 source.** The 1.6.0 phone-check screen
  shown on the page is a development build; the roadmap labels it that way.
  Publishing 1.6.0 needs the owner’s signing run from a clean commit and the
  phone acceptance record.
- **No public ratings or testimonials.** The page uses product facts and
  published limits instead. That is a deliberate difference from ScreenZen,
  Covenant Eyes and the app-store pages.
- **Arabic is drafted, not native-reviewed.** The product page’s Arabic is in
  `lib/site.js`; the Vault’s is in `lib/copy.js`.
- **No real phone browser pass.** The layout was checked in headless Chrome at
  1280 px and 390 px; the Android app captures came from the emulator, not a
  retail phone.
- **One RTL screenshot caveat.** Headless Chrome’s full-page capture shifts a
  right-to-left page on the right edge; the viewport capture
  (`design/website-2026-11-14/hero-ar.png`) is the one that shows the real
  layout. The page itself reports no horizontal overflow in either language.
- **No analytics, cookies or third-party script** was added, and the CSP blocks
  connections on the product and privacy pages.
