# Hisn 1.0 readiness

Updated 6 November 2026. This is the single finish-line view across platforms.
It distinguishes **code and local verification** from **signed distribution and
device proof**; the second list is not something a repository can complete.

## What is code-complete

### Unlisted-host guard (2026-11-06)

- **Adult-TLD rail on every client.** A host whose final label is `.adult`,
  `.porn`, `.sex` or `.xxx` is blocked without a list entry: the extension's
  `rules/adult_tlds.json`, `AdultTldGuard.swift` in the Mac filter and site
  checker, four rules in the last Safari blocker (236,590 generated rules in
  total), and `AdultTldPolicy.java` in Android DNS. `.cam` is deliberately
  excluded; the hand allowance still wins.
- **Android hostname-keyword parity.** `HostTermPolicy` applies the signed
  116-term layer (59 token, 57 substring) with `never_keyword` and exempt-host
  rules, loaded synchronously from the digest-pinned `terms.json` before the
  DNS tunnel starts. All 42 shared `host_cases.json` cases pass, plus the named
  safety cases.
- **Shared contract.** Five new `policy_cases.json` entries are asserted by
  both the Mac and browser suites; the browser has a 63-check ruleset test and
  the iOS builder has guard, capacity and URL-boundary tests.
- Evidence, limits and the exact test counts:
  [BLOCKING_GUARD_2026-11-06.md](BLOCKING_GUARD_2026-11-06.md). No signed
  artifact or device acceptance is claimed.

### Browser extension 1.5.0

- Blocking, SafeSearch, text scanner, optional local visual checks, short-video
  rules and pause screen.
- **Move your rules (Workstream A1, extension side).** Settings → Blocking
  Rules exports the five hand lists as a versioned `hisn.rules` JSON file and
  imports one add-only. Import never removes an entry, so a more permissive
  file cannot undo a stricter browser; a running lock withholds new allowlist
  and correction entries and applies new blocks and words; an app-managed
  browser refuses the import because its lists belong to the Mac app. The file
  contains no mode, deadline, list generation, pause count or browsing data.
- **Language-aware text scoring.** Every reviewed word carries a language. The
  page's own text, not only its tag, chooses the English, Arabic, German,
  Spanish, French, Italian or Portuguese vocabulary; explicit strong labels and
  every negative phrase remain available in every language; an unidentified
  language falls back to the full list. The popup shows the detected language
  and the options page explains the rule.
- **UI/UX pass.** One status hero, one-word layer states, a compact app and
  block-list row, and shortened English/Arabic copy. Design captures are in
  `design/extension-ui-2026-11-02/`; no policy changed.
- Signed list update with a manual refresh and a 14-day age warning; Strict-mode
  preservation across a mode-less bridge reply.
- Options footer with on-device statement, version and privacy/support links.
- Store metadata, permission set (unused `offscreen` removed) and
  [EXTENSION_STORE.md](EXTENSION_STORE.md) listing/privacy/managed-policy record.
- Package: `dist/hisn-extension-1.5.0.zip`, 92 files, 5.9 MB, SHA-256
  `96ca854f52b3a4cb406bcc735013263a6adea56aedda93c843bf95733b1d85a7`.
- Seed v5 core tier: 239,885 domains, 480 static DNR rules.
- Evaluation corpus at sensitivity 50/80/100: 0/22 adult cases missed, 0/28
  benign pages blocked. The real-engine visual smoke now runs flat green, flat
  blue, a soft gradient and a checkerboard.

### Mac 1.1.11 (historical)

- **UI/UX pass:** Overview is one status hero with a tile per layer and a

  decide an address. It prefers the installed generation, falls back to the

- **Browser-guard warning:** a calm dark card with a shield, the browser name,

- **Pause window:** a 30-second guided breath, five rotating reminders, four

  Overview, the menu bar and ⇧⌘P; available during a lock; closing is always

- Root guardian daemon in the system domain, installer wiring, local action log
  and an in-app last-action row.
- **Protection authority:** Setup reads whether the daily account is standard,

- Details shows list freshness and last update failure.

### iPhone & iPad 1.5.0

- **UI/UX pass:** the overview is a calm card stack (status, pause, plan
  progress, lock and rules); the lock, blocked-site and app-limit cards open
  their editors directly; Setup is three guided steps with a checks card; the
  app-limit editor shows always block, daily budget and quiet hours as visible
  rows; Settings is grouped cards. Long scope copy is behind per-section
  disclosures, Setup issues collapse behind a count, stale "Hisn 1–4" guide text
  is corrected to 1–6, and the overview uses short state labels. Every tab and
  the three Setup drill-ins are rendered at phone and iPad sizes in English and
  Arabic, phone light and dark. No rule, lock or enforcement path changed.
- **Custom Screen Time shield:** HisnShieldConfig names the saved rule — always
  block, daily budget reached or quiet hours — in English or Arabic, and
  HisnShieldAction offers only Close. It cannot unlock or weaken a rule; a
  missing or unreadable rule gets an honest generic message. Both extensions
  carry the Family Controls entitlement and a privacy manifest.
- **On-demand pause:** a 30-second guided breath, five rotating reminders, four
  needs with offscreen tips and a local day/count tally. It is available during
  a commitment, closes immediately and changes no protection rule.
- **Protection hero:** one status, layer chips and one next action at the top of
  the overview; the full diagnostics are one disclosure below.
- **Daily quiet hours:** a DeviceActivity window applies the selected apps'
  shields, splits a cross-midnight window into two same-day legs, enforces
  Apple's 15-minute minimum and clears only when both the device clock and, once
  read, Apple's server time are outside the window. The health row distinguishes
  registered from stopped; a commitment freezes the rule and the guardian path
  can tighten, never loosen it.
- **Protection lock:** while a commitment runs, the saved blocked-site list and
  app-limit rules are frozen — no additions, removals or changes. An unreadable
  commitment counts as locked. Protection layers can still be added or restored,
  never turned off. Extending the commitment remains available.
- Screen Time filter, app shields/budgets, six Safari blockers, Safari text
  extension, passcode vault, trusted time, layer alerts and supervised profile.
- Privacy manifest in the app and all six extensions; export-compliance
  declaration.
- Settings links, app version and offline licenses/sources screen.
- Signed Safari list age warning after 90 days.
- Optional supervised-profile hardening keys, each opt-in.
- Six Safari blockers of 40,000 rules each; seed v5 fits with 115 entries of
  headroom.

### Android 1.1.0

- **UI/UX pass:** a three-page, skippable first-run welcome in English and
  Arabic; a voluntary **Take a pause** row on Protection that changes no rule;
  and today's **Used X of Y** usage with a progress bar in the daily-limit
  editor. The welcome appears only when no rules are configured. ScreenZen's
  Android onboarding was observed read-only as design input; no competitor code,
  assets or copy was used.
- **Daily time limits:** one foreground-time limit per chosen app, from five
  minutes to 24 hours. Android's own on-device usage record is read only after
  the person grants Usage access; a missing grant is shown, never reported as
  enforced. The limit is frozen by a protection lock, a guardian path preserves
  saved limits and cannot remove or raise them, and system apps, dialers,
  launchers and Hisn itself stay excluded. Nothing is uploaded.
- **Signed direct release:** the 1.1.0 direct APK is signed with the local
  release key, checked by `check-release.py` and published at
  [the android-1.1.0 release](https://github.com/hamzabinjehad/AdultContentBlocker/releases/tag/android-1.1.0);
  the Play build is produced but not uploaded, and the direct removal guard is
  deliberately absent from it.
  The 1.0.0 → 1.1.0 update succeeded in place on the owner's Samsung and the
  Arabic welcome rendered; no full physical-phone enforcement run is claimed.
- DNS filtering, selected-app/text/visual checks, schedules, protection locks,
  direct build's screen guard (removal, disable, Safe Mode and new-install
  screens) and boot shield.
- **Protection lock:** while the in-app lock runs, every saved rule is frozen in
  both directions — domains, words, apps, schedule, built-in switches,
  SafeSearch and gray screen. The rule backend refuses changes for every caller;
  only a guardian-signed policy may add restrictions. The direct build's removal
  guard arms itself from the lock, and a device-owner install applies Android's
  uninstall block. The Play build states that it cannot block its own removal.
- Optional device-owner uninstall block and managed lockdown: Safe Mode, all-app
  controls, Settings factory reset, new users, VPN, manual date/time on
  Android 9+, Private DNS on Android 10+, default-app changes on Android 14+,
  an optional strict unknown-source install block, an opt-in suspension of
  blocked apps, a one-tap keep-only browser selection, an opt-in SafeSearch
  CNAME rewrite, and an always-on DNS-only VPN while DNS filtering is on.
- Persistent 15-minute layer watchdog with visible last-run/lost/notifications
  state and notification permission request.
- APK-only list decision with a 90-day warning; Play/direct verifier; release
  APK/AAB checks.
- Seed v5: 239,885 signed core domains, 239,880 loaded after the client's
  IP-entry exclusion; notices name the two selected fill sources.

## What is not proven

- No signed/notarized Mac package, no Developer ID, no app updater.
- No Apple Developer team, Family Controls distribution entitlement, TestFlight
  build or physical iPhone/iPad result.
- The 1.0.0 direct and Play APKs are signed with a locally generated release
  key; its backup custody, Play listing and a physical device-owner run remain.
  An API 36 emulator run on 2026-11-01 proved nine lockdown
  restrictions, strict mode, blocked-app suspension readback, the app's own
  uninstall refusal, and release cleanup (suspension resumed, always-on cleared,
  ownership removed, ordinary uninstall allowed). A Java pairing/policy
  exchange with the Python reference also passed on the emulator, including
  applying a Python-signed tighten-only policy (including a blocked package and domain) and reading back `protected`
  with an EC key in AndroidKeyStore on API 31+, and the product manual pairing
  screen (paste offer, SAS, copy response) was verified on the emulator. The
  camera QR flow and a physical phone remain unproven; the signed domain-list
  hash is verified in both Python and Java. On 2026-11-02 the 0.9.0 protection
  lock was started through the product UI on the same emulator, its disabled
  rules were read back through the accessibility tree, the Arabic capture was
  taken, and `CoreDeviceTestRunner` passed the full-freeze assertions. On
  2026-11-03 the 1.0.0 time-limit card was read back and a 5-minute limit was
  reached by the test-only fixture app, closed and explained on the same
  emulator; no physical-phone 1.0.0 run is claimed.
- No Chrome Web Store listing, real store ID, review or managed force-install.
- No **scheduled** list publication: the `list-signing` GitHub environment is
  not configured. v6 was published once with the matching local key; no
  installed client is proven to have installed it.
- The Mac app still bundles the 239,885 core tier. The v6 branch carries the
  5,274,046-domain full list, but the filter loads it only after the app's
  updater runs on an installed build.
- No physical standard-account Mac bootout/reboot test for the guardian daemon.
- No real-app text/visual benchmark with licensed content and denominators.
- No cross-device export/import, device-proven always-on DNS VPN, iOS URL filter
  or time-locked removal password. The DNS-only always-on request exists but is
  not tunnel-tested on a device.
