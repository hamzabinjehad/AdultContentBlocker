device proof**; the second list is not something a repository can complete.

## What is not proven

- No signed/notarized Mac package, no Developer ID, no app updater.
- No Apple Developer team, Family Controls distribution entitlement, TestFlight
  build or physical iPhone/iPad result.
- No signed Android APK with a production key, no Play listing, no
  device-owner/provisioned-phone acceptance.
- No Chrome Web Store listing, real store ID, review or managed force-install.
- No published `lists` branch; every client is still on seed v4.
- No physical standard-account Mac bootout/reboot test for the guardian daemon.
- No real-app text/visual benchmark with licensed content and denominators.
- No cross-device export/import, always-on VPN, iOS URL filter or time-locked
  removal password. These are explicitly deferred, not silently claimed.

## Owner actions to finish distribution

1. **Apple**
   - Join the Developer Program; request the Family Controls distribution
     entitlement for the app and `HisnActivityMonitor`.
   - Set the team, sign, archive and upload to TestFlight.
   - Host the privacy/support pages and match the App Store privacy label.
   - Test on a disposable iPhone/iPad: vault, Screen Time readback, app shields,
     Safari blockers, supervised profile, revocation and reboot.
2. **Android**
   - Create the production keystore offline with two backups; build/sign; record
     the certificate and APK hash.
   - Provision a disposable device owner and prove uninstall/Safe Mode/app
     controls/factory reset/VPN/Private DNS refusals and release.
   - Run the layer-loss, VPN handover and real-app checks; then decide Play vs
     direct for the public build.
3. **Mac**
   - Obtain a Developer ID Application and Installer identity; build, sign,
     notarize and staple the `.pkg`.
   - Run the standard-account guardian-split, bootout, reboot and admin-recovery
     tests; publish an updater path.
4. **Extension**
   - Open the Chrome Web Store developer account; upload the 1.2.1 zip unlisted.
   - Fill the listing/privacy answers from `EXTENSION_STORE.md`; read the store ID
     and wire it into the native host, Mac profile and Windows policy.
   - Test managed force-install on a standard user.
5. **Lists**
   - Configure the `list-signing` environment on `main`, publish the `lists`
     branch and prove an update on each client.
6. **Docs**
   - Host `PRIVACY.md` and `SUPPORT.md` at stable URLs; record every device result
     in `RELEASE_VALIDATION.md` and the platform release record.

Until those are done, the honest label is **release candidates**, not 1.0.
The repository side is ready for them.
