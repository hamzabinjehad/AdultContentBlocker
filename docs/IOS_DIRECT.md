# Installing Hisn on iPhone without the App Store

Hisn's iPhone/iPad build is distributed directly: an IPA on any HTTPS host,
signed on install by the person's own Apple team (or by a self-signing
installer). This is the path the project chose for 1.8.0 and later. It is
**not** an App Store submission, and it does not pretend Apple's platform
rules stopped applying.

Read this whole page before publishing a download link. The short version:

- iOS still enforces code-signing entitlements. A sideloaded IPA is not a
  jailbreak, and "outside the App Store" does not make `Family Controls`,
  Network Extensions or App Groups appear in a profile that does not have
  them.
- The DNS filter needs **Network Extensions (`dns-proxy`)**.
- The Screen Time layers need **Family Controls**, which Apple grants only
  after a request and review. The direct build runs the same entitlement
  request as the App Store build; distribution does not bypass it.
- The IPA built by this repository is unsigned. It will not install on a
  stock iPhone until an installer signs it.

## What is in the direct build

The same app CI tests, not a reduced edition:

- six Safari content blockers with 236,586 signed domains and the four
  adult-TLD rules;
- the Hisn Text Safari extension with its text and optional visual checks;
- the **device-wide DNS filter** (`HisnDNSProxy`) with the signed domain list,
  adult TLDs, review hostname terms and the person's saved sites;
- Screen Time app rules, the daily budget, quiet hours, the pause rule, the
  shield extensions and the browser/VPN guard;
- the commitment, the passcode vault, the Lock Center and the bilingual UI.

The one screen that is not the App Store one is the installation: no review,
no TestFlight, no store listing.

## Build the IPA

From the repository root, on a Mac with Xcode and Python 3:

```sh
python3 ios/generate_xcodeproj.py            # only after source membership changes
./ios/direct/build_direct.sh                  # unsigned: dist/ios/Hisn-<version>-<build>.ipa
./ios/direct/build_direct.sh --adhoc          # also ad-hoc signs each bundle
./ios/direct/build_direct.sh --source-url https://example.com/Hisn.ipa \
    --out dist/ios                            # also writes the AltStore source JSON
```

The script builds Release for `generic/platform=iOS`, then refuses to package
unless all of these are inside the app:

- `Hisn1.appex` … `Hisn6.appex` with `rules.json` and `rules-metadata.json`;
- `HisnText.appex`, `HisnActivityMonitor.appex`, `HisnShieldConfig.appex`,
  `HisnShieldAction.appex`;
- `HisnDNSProxy.appex` with `dns-domains.txt`, `dns-host-terms.json` and
  `dns-metadata.json`;
- the app's own `rules-metadata.json`.

It writes `build-info.json` (version, build, byte size, SHA-256, signed state,
UTC build time) next to the IPA. The version and build come from the app's
`Info.plist`; do not type them into a release page by hand.

`--adhoc` signs each nested extension first, then the app, applying the
entitlement files in `ios/Hisn/Hisn.entitlements` and
`ios/HisnDNSProxy/HisnDNSProxy.entitlements`. That is useful for an installer
that preserves an existing signature and for inspecting the requests with
`codesign -d --entitlements`. It does not make the IPA installable on a stock
device.

## Publish a source people can add

AltStore and SideStore read a JSON source. `ios/direct/make_source.py` writes
it from the IPA, so the size and SHA-256 cannot disagree with the file:

```sh
python3 ios/direct/make_source.py \
  --ipa dist/ios/Hisn-1.8.0-14.ipa \
  --url https://example.com/hisn/Hisn-1.8.0-14.ipa \
  --out public/source.json
python3 ios/direct/make_source.py --check public/source.json
```

Host both files over HTTPS. The source names the icon URL, the website, the
tint colour and the entitlements the app will ask the installer for. Updating
the download in place is not enough: bump `MARKETING_VERSION` and
`CURRENT_PROJECT_VERSION` in `ios/generate_xcodeproj.py`, rebuild, and add the
new version entry to the source. `--check` fails on a missing SHA-256, an HTTP
URL, a duplicate version/build or a bundle identifier that is not
`app.hisn.mobile`.

The version build in `versions.json` must change with the app, as for every
other platform. The release checklist is in
[RELEASE_RUNBOOK.md](RELEASE_RUNBOOK.md); the version page is generated by
`python3 script/versions.py`.

## Install paths

| Path | What it needs | What it can grant | Read this first |
| --- | --- | --- | --- |
| **AltStore / SideStore** | A paid Apple Developer Program membership is the practical option; a free Apple ID cannot use Network Extensions and re-signs every 7 days | The capabilities your App ID and provisioning profile include. App Groups and Network Extensions come from the team's capabilities; Family Controls needs Apple's approval on top | Signing in with an Apple Account gives the installer a development certificate for that account. Free accounts do not include the restricted entitlements. |
| **Xcode on a Mac** | The person's paid team, the device connected, the capabilities enabled in the App ID | Same profile rules as above; best path to test what actually works | Open `ios/HisnMobile.xcodeproj`, set the team on all targets, select the device, Run. The Simulator cannot use a Network Extension provider. |
| **TrollStore** | A supported iOS version and device; no Apple account | TrollStore installs the IPA with its own signing primitive. Which entitlements are honoured depends on the iOS version and TrollStore build, and a sandboxed entitlement is still enforced | A community tool, not an Apple-supported route. Verify on the actual device that the DNS extension and Screen Time layers operate; do not publish "works" from an install alone. |
| **Jailbroken device** | A jailbreak and a package manager | Full control of the platform | Hisn does not ship a jailbreak tweak. Running the direct build with a jailbreak is the person's own configuration. |
| **Hisn Safari limited edition** | A free Apple ID, Xcode | Safari blockers only | `ios/HisnSafariOnly/README.md`; no DNS filter, app shields, scanner, commitment or deletion protection. |

Apple's normal recovery paths remain: a device passcode, the Apple Account
password, Screen Time settings, or erasing the device can remove the app or
its rules. Nothing in the direct build changes that. The app's own Lock Center
says the same thing.

## Which capabilities to enable

In the Apple Developer portal, for the app identifier `app.hisn.mobile` and
its extensions:

| Capability | Entitlement | Needed by | Apple's process |
| --- | --- | --- | --- |
| App Groups (`group.app.hisn.mobile`) | `com.apple.security.application-groups` | app, DNS proxy, monitor, shield config/action | Self-serve |
| Network Extensions → DNS Proxy | `com.apple.developer.networking.networkextension` = `dns-proxy` | app, `HisnDNSProxy` | Self-serve for a paid team; confirm the capability is offered in your account |
| Family Controls | `com.apple.developer.family-controls` | app, monitor, both shield extensions | [Request and approval](https://developer.apple.com/documentation/familycontrols/requesting-the-family-controls-entitlement) |

The entitlement plists are **requests**. If the profile does not carry the
entitlement, the app will not launch with it. A profile with only
`dns-settings` is not enough for 1.8.0: the old DNS-settings path was replaced
by the DNS proxy, so reissue the profile. If you do not have Family Controls
approval, the app bundle cannot be signed into a working install with the
shield extensions; the Safari-only limited edition is the build that does not
need it.

## What the app does with the network

- The DNS extension's own HTTPS requests go to `1.1.1.3` and `1.0.0.3`
  (Cloudflare Families). They are the only upstream resolver, they are made by
  IP literal, and their certificate carries those IP addresses.
- No browsing history, domain log, query text or route is stored. The app keeps
  only what the UI shows: counts, states, the commitment, the person's saved
  lists and the route-check result.
- The route check asks for a random name under `hisn.invalid`, a reserved and
  unresolvable domain, and expects the extension's own `203.0.113.7`. If the
  filter is off, the name fails; no real site is contacted.
- The DNS extension cannot see other traffic, and Hisn does not install a
  packet tunnel or a full VPN.

## Verifying a build before publishing

```sh
shasum -a 256 dist/ios/Hisn-1.8.0-14.ipa     # compare with build-info.json
plutil -p dist/ios/Payload/HisnMobile.app/Info.plist   # version and build
unzip -l dist/ios/Hisn-1.8.0-14.ipa | grep -E 'appex|dns-'   # extension data
python3 ios/direct/make_source.py --check public/source.json
```

Then install it on the *actual* device and record what happened: the VPN
permission prompt, `Hisn DNS` in Settings → General → VPN & Device Management,
the route check, a blocked name in Safari and in a non-WebKit app, and the
extension still present after a reboot and a relaunch. The repository's
[PHYSICAL_DEVICE_VALIDATION.md](PHYSICAL_DEVICE_VALIDATION.md) is the record
template. A successful install is not a blocking test.

## Legal and safety notes for a download page

- Say plainly that this is not an App Store app, that the installer signs it
  with the user's own Apple team, and that restoring a backup, erasing the
  device or removing the profile removes it.
- Link to [PRIVACY.md](../PRIVACY.md) and [SUPPORT.md](../SUPPORT.md), and say
  that the DNS filter sends allowed names to Cloudflare.
- Never publish an IPA from this repository as "unremovable", "undetectable" or
  "bypasses Screen Time". The Lock Center's own words are the ceiling of what
  may be claimed.
- Sideloading is the person's choice and their risk. No warranty is added by
  this page; the repository's license still applies.
