## Version notes

- **Browser extension (Chromium)** (`extension`): The packaged zip strips the development key; the Chrome Web Store ID will differ from the unpacked ID.
- **Mac** (`macos`): Every target must carry the same MARKETING_VERSION and CURRENT_PROJECT_VERSION.
- **iPhone & iPad** (`ios`): The app, Safari blockers and HisnActivityMonitor share one version set; 1.1.3 adds the privacy manifest, export compliance, signed list age and policy links.
- **Android** (`android`): versionCode is monotonic and must increase for every uploaded or side-loaded update. 21 adds the bundled-list freshness warning, watchdog status, the list-update decision and notification permission on top of 0.8.0 (API-29 Private DNS and the layer watchdog).

## Bumping a version

1. Bump the platform's own manifest: `extension/manifest.json`,
   `android/app/build.gradle`, or the Xcode target's `MARKETING_VERSION` and
   `CURRENT_PROJECT_VERSION`.
2. Change the same value in `versions.json` and update its `updated` date.
3. Run `python3 script/versions.py` to regenerate this page, then
   `python3 script/versions.py --check` (also part of `./test.sh python`).
4. Add the release notes to `CHANGELOG.md`. A version bump without a changelog
   entry is an unfinished release.

Android `versionCode` only ever increases. iOS and macOS build numbers only
ever increase for a shipped build. The extension version must match the
packaged zip name; the store assigns its own extension ID, not a version.
